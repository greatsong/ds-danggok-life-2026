이름은 사람이 붙인다

🎯 오늘 만드는 것
  • 동물 무리 성격 찾기 앱 — 동물 이름을 검색하면 소속 묶음과 그 묶음의 프로파일(체중·수명), 내가 붙인 이름을 보여 주는 앱 (배포까지)

0. 왜 배우나

지난 두 시간 동안 컴퓨터가 한 일은 여기까지입니다. 포유류 784종을 세 무리로 갈랐고, 각 무리에 0·1·2라는 번호를 붙였습니다. 그런데 이 결과를 그대로 발표하면 아무도 알아듣지 못합니다. "묶음 1에 274종이 들어갔습니다"는 사실의 나열일 뿐입니다. 누군가 "그래서 그게 어떤 동물들인데?"라고 물으면, 그 답은 데이터 어디에도 적혀 있지 않습니다. 오늘 하는 일이 그 답을 만드는 일입니다. 숫자를 근거로 무리에 이름을 붙이고, 그 이름을 담은 앱을 배포해 남이 써 볼 수 있게 만듭니다. 계산이 끝나는 자리에서 데이터 과학의 마지막 한 걸음이 시작됩니다.

1. 개념 이해 — 이름을 붙이는 책임

컴퓨터가 주는 것과 주지 않는 것

k-means가 내놓는 것은 번호가 붙은 묶음들뿐입니다. 묶음 0·1·2라는 번호에는 아무 뜻이 없습니다. 알고리즘이 다루는 것은 점들 사이의 가까움과 멂이라는 기하학이고, 그 구조에 의미를 붙이는 일은 알고리즘의 능력 밖입니다. 어떤 무리가 "코끼리처럼 크고 오래 사는 무리"인지 읽어내려면 데이터 밖의 지식, 곧 우리가 동물에 대해 아는 것이 필요합니다. 패턴을 찾는 일은 기계가, 뜻을 붙이는 일은 사람이 맡는 나눔입니다.

이름은 해석이고, 해석에는 근거가 있어야 한다

이름은 정답이 아니라 해석입니다. 그렇다고 아무렇게나 불러도 되는 것은 아닙니다. "이 무리는 중앙값이 70kg·30년이니 대형 장수형"처럼 숫자를 근거로 대면, 남이 확인하고 반박할 수 있는 해석이 됩니다. 반대로 근거를 대지 못하는 이름은 인상에 지나지 않습니다. 같은 무리에 두 사람이 다른 이름을 붙였더라도, 둘 다 프로파일 숫자를 근거로 삼았다면 어느 쪽도 틀렸다고 하기 어렵습니다. 해석에서 따지는 것은 이름의 일치가 아니라 근거의 유무입니다.

세 트랙이 남긴 하나의 물음

회귀에서는 조건을 바꾸자 R²가 달라졌고, 분류에서는 정확도가 기준선 위인지 물었고, 군집에서는 점수가 정답을 주지 않았습니다. 다루는 도구는 셋이었지만 물음은 하나였습니다. 이 결과를 언제, 얼마나 믿을 수 있는가. 오늘 붙이는 이름도 같은 물음 아래 있습니다. 이름을 붙였다고 그 무리의 성격이 확정되는 것이 아니라, 어떤 근거에서 그렇게 불렀는지가 함께 남아야 다음 사람이 검토할 수 있습니다.

2. 컴퓨터는 묶기만 한다

  • 지난 두 시간, 컴퓨터는 포유류를 몸 프로파일이 비슷한 묶음으로 나눴다.
  • 그런데 컴퓨터가 준 건 묶음 0, 묶음 1, 묶음 2라는 번호뿐이다. 그 번호엔 뜻이 없다.
  • 이 묶음이 "코끼리 같은 대형 장수형"인지 "생쥐 같은 소형 단명형"인지 읽어내는 건 사람의 몫이다. 오늘의 마지막 한 걸음.
⚠️ 묶음 번호는 실행마다 바뀐다
  • k-means의 묶음 번호(0·1·2)는 돌릴 때마다 순서가 달라질 수 있다.
  • 그러니 번호를 외우지 말고, 묶음의 프로파일(중앙값 체중·수명)을 보고 이름을 붙인다.

3. 묶음의 프로파일 읽기

  • 각 묶음의 중앙값 체중과 수명을 재면 성격이 보인다. 세 묶음의 중앙값은 이렇게 나온다.
중앙값 프로파일어떤 무리일까이름 후보
체중 약 70kg · 수명 약 30년크고 오래 사는 동물 (코끼리·고래·사람)대형 장수형
체중 약 2.5kg · 수명 약 18년중간 크기 동물 (개·여우 무리)중형
체중 약 66g · 수명 약 6년작고 짧게 사는 동물 (생쥐·땃쥐 무리)소형 단명형
💡 이름의 근거를 말로
  • "이 묶음은 중앙값이 70kg·30년이니 대형 장수형"처럼, 프로파일 숫자를 근거로 붙인다.
  • 이름은 정답이 아니라 해석이다. 근거만 또렷하면 다르게 불러도 된다.

4. 검색 앱 만들고 배포하기 (①②③)

  • 만들 것 = 동물 이름을 넣으면 소속 묶음 + 묶음 프로파일 + 내가 붙인 이름이 뜨는 앱
  • requirements.txt에는 scikit-learn만 (기본 설치 제외 · 버전 없이).
① 샘플 프롬프트
포유류 군집 앱을 배포용으로 정리해 줘. 스트림릿 클라우드에 올릴 거야. 조건:

- 포유류만 골라서 체중, 수명, 성숙 시기, 임신 기간 네 가지로,
  앞서처럼 로그와 표준화를 거쳐 k-means 3묶음으로 나눠 줘.
- 묶음마다 중앙값 체중을 재서, 큰 순서대로 대형 장수형, 중형,
  소형 단명형이라고 자동으로 이름을 붙여 줘.
- 위에 동물 이름을 입력하는 검색창을 둬. 동물을 넣으면 그 동물이
  어느 무리인지 알려 주고, 그 무리의 중앙값 체중과 수명도 보여줘.
- 한국어 라벨, 따뜻한 톤, 초보자용 한국어 주석. main.py 전체 코드를 한 번에 줘.
- 필요한 라이브러리 목록(requirements.txt)도 버전 없이 같이 줘.
② AI가 준 코드 예시
import streamlit as st
import pandas as pd
import numpy as np
from sklearn.preprocessing import StandardScaler
from sklearn.cluster import KMeans

st.title("🧬 동물 무리 성격 찾기")

@st.cache_data
def load():
    url = "https://raw.githubusercontent.com/greatsong/modudata/main/data/life_animals.csv"
    return pd.read_csv(url)

df = load()

# 포유류만, 몸 프로파일 네 가지로 (로그와 표준화)
m = df[df["class"] == "Mammalia"]
feats = ["adult_weight_g", "max_longevity_yrs", "female_maturity_days", "gestation_days"]
a = m.dropna(subset=feats).copy()
Xs = StandardScaler().fit_transform(np.log10(a[feats]))
a["묶음"] = KMeans(n_clusters=3, random_state=42, n_init=10).fit_predict(Xs)

# 중앙값 체중이 큰 순서대로 이름을 붙인다 (번호는 실행마다 바뀌므로)
순서 = a.groupby("묶음")["adult_weight_g"].median().sort_values(ascending=False).index
이름 = {순서[0]: "대형 장수형", 순서[1]: "중형", 순서[2]: "소형 단명형"}
a["무리"] = a["묶음"].map(이름)

# 동물 검색
q = st.text_input("동물 이름을 입력하세요(영문)", "Human")
hit = a[a["common_name"] == q]
if len(hit) > 0:
    cl = int(hit["묶음"].iloc[0])
    st.subheader(f"{q} → {이름[cl]}")
    무리 = a[a["묶음"] == cl]
    st.write("이 무리의 중앙값 — 체중",
             f"{무리['adult_weight_g'].median():.0f} g · 수명",
             f"{무리['max_longevity_yrs'].median():.1f} 년")
else:
    st.info("그 동물을 찾지 못했어요. 영문 이름을 다시 확인해 주세요.")
✔️ 실행하면 이렇게 나온다
  • Blue whale·Human·Chimpanzee를 검색하면 대형 장수형에 들어간다.
  • Domestic dog를 검색하면 중형, 작은 땃쥐 무리는 소형 단명형에 들어간다.
  • 중앙값을 보고 이름이 대형 장수형·중형·소형 단명형으로 자동으로 붙으면 완성.

5. 군집 트랙 마무리

  • 비지도학습으로 동물을 묶고(12차시), 그 묶음을 언제 믿을지 확인하고(13차시), 오늘 뜻을 붙였다.
  • 데이터 과학의 마지막 한 걸음은 계산이 아니라 해석이다.
✔️ 세 트랙을 지나며 배운 것
  • 회귀: 직선을 그어도 언제 믿을 수 있나를 먼저 묻는다.
  • 분류: 정확도가 높아도 무엇을 놓쳤나를 본다.
  • 군집: 점수가 정답을 주지 않기에 사람이 이름을 붙인다.

7. 해보기 — 개인 또는 팀

✏️ 개인 미션 — 이름의 근거 (10분)
  • 내가 붙인 묶음 이름 세 개와, 각 이름을 붙인 근거(중앙값 체중·수명)를 한 줄씩 적는다.
  • 배포한 앱 주소를 갤러리에 올린다.
🗣️ 팀 미션 — 이름이 다르면 누가 맞나 (2~3인 토의, 7분)
  • 짝 팀과 묶음 이름을 비교한다. 같은 무리에 다른 이름을 붙였다면, 각자 중앙값 표의 어느 숫자를 근거로 들었는지 서로 설명한다.
  • 토의 질문: "근거가 다 또렷하다면, 이름이 달라도 둘 다 맞다고 할 수 있는가?" 입장을 한 문장으로 적는다.
  • 근거를 대지 못하는 이름이 있었다면, 중앙값 표를 다시 보고 근거부터 채운다.
🧾 이 기록이 수행평가 재료가 된다
  • 배포한 앱 주소(URL)와 갤러리 게시는 세 번째 배포 증빙으로 수행평가 기록에 남는다. 이름의 근거 한 줄들은 팀 프로젝트 발표 3줄(질문·데이터·발견)의 연습 재료다.

8. 확인 문제

지필 문항과 같은 유형입니다. 먼저 스스로 답을 적고 나서 펼쳐 보세요.

문제 1 — "군집의 이름은 사람이 붙인다"가 뜻하는 바를 서술하시오.

예시 답안 — 컴퓨터가 주는 것은 묶음 0·1·2라는 번호뿐이고 번호에는 뜻이 없다. 그 무리가 대형 장수형인지 소형 단명형인지 읽어내는 데는 데이터 밖의 생물 지식이 필요하므로, 패턴 발견은 기계가 해도 의미 부여는 사람이 한다는 뜻이다.

문제 2 — "0번 묶음은 대형 장수형"이라고 번호로 외우면 안 되는 이유와, 대신 무엇을 보고 이름을 붙여야 하는지 서술하시오.

예시 답안 — k-means의 묶음 번호는 실행마다 순서가 바뀔 수 있어, 번호로 외우면 다음 실행에서 어긋난다. 번호가 아니라 묶음의 중앙값 프로파일(체중·수명)을 보고 큰 쪽부터 이름을 붙여야 한다.

문제 3 — 사람(Human)이 든 무리를 '대형 장수형'이라 부를 수 있는 근거를 데이터에서 들고, 그 이름이 사람이라는 종 하나를 다 설명하지는 못하는 이유를 함께 서술하시오.

예시 답안 — 사람은 체중 62kg으로 이 무리의 중앙값 70kg 언저리에 놓이므로 대형 장수형이라 부를 근거가 있다. 다만 수명 122년은 무리 중앙값 30년을 크게 넘어서, 이름은 무리 전체의 평균적 성격을 가리킬 뿐 그 안의 개별 종이 어디까지 예외인지는 따로 확인해야 한다.
